01 · WHAT IS n8n & CORE ARCHITECTURE

Open-source workflow automation platform (self-host or cloud)
500+ built-in integrations (nodes) for apps, APIs, databases

02 · APIs & WEBHOOKS Video 2
🔌APIs — How n8n Uses Them
What is API
Interface for apps to talk to each other. Sends/receives structured data (usually JSON)
REST API
Uses HTTP methods: GET (read), POST (create), PUT (update), DELETE (remove)
Auth methods
API Key in header, OAuth 2.0 (token-based), Basic Auth (user:pass), Bearer token
HTTP Request
Universal node — call ANY REST API even without a native n8n node
Response
Always JSON — passed as items to next node in the workflow
🪝Webhooks
Definition
Push-based: external service sends data to n8n instantly when event fires
vs Polling
Webhooks are event-driven (real-time); polling checks repeatedly on schedule
Test URL
Use during development — displays data live in canvas
Prod URL
Active after workflow published — runs silently in background
Max payload
16 MB (configurable via N8N_PAYLOAD_SIZE_MAX env var)
Headers Body (JSON) Query Params Path Params

04 · DATA HANDLING IN n8n Video 4
📦Data Structure
All data flows as an array of items (JSON objects)
Each item = { json: {...}, binary: {...} }
Nodes process items one by one unless explicitly looped
Reference fields with {{ $json.fieldName }}
Access previous node: {{ $node["NodeName"].json.field }}
Binary data (files, images) stored separately in binary key
// Item structure [ { "json": { "name": "Alice", "email": "..." } }, { "json": { "name": "Bob", "email": "..." } } ]
🔄Expressions & Variables
$json
Current item's JSON data
$input
All input items (array)
$node[name]
Data from a specific named node
$now
Current timestamp (ISO format)
$vars
Workflow variables (persistent)
$env
Environment variables
$workflow
Workflow metadata (id, name)
$runIndex
Current iteration index in loop
🔀Logic Nodes Compared
NodeUse WhenOutputs

💡
Split > Process > Merge is the most common pattern for handling multiple items differently then re-combining them.
05 · ERROR HANDLING & DEBUGGING Video 3–4
🛡Error Handling Strategies
Continue on Error
Node setting — workflow continues even if this node fails; error passed as output
Error Output
Enable on node → splits into Success + Error branches for fine-grained control
Error Workflow
Dedicated workflow triggered by Error Trigger — catches failures, sends alerts via Slack/email
Stop & Error Node
Deliberately halt with descriptive message to prevent bad data propagating
Retry on Fail
Node setting — auto retry N times with delay (good for flaky APIs)
API Call
→
✓ Success
/
✗ Error → Log
🔬Debugging Techniques
Execution Log — inspect every node's input & output after a run
Pin Data — freeze a node's output to test downstream nodes without re-triggering
Edit Output — manually override node output to simulate edge cases
Debug Node — drop inline to inspect data at any point in real-time
Red node indicator — visually shows exactly where failure occurred
Server logs — console output for complex self-hosted debugging
💡
Workflow = Plumbing. Always pin data on complex nodes first, test logic nodes independently, then connect end-to-end.

08 · EXAM QUICK-FIRE FACTS
🎯Must-Know Distinctions
TopicKey Fact
IF vs SwitchIF = 2 outputs (true/false). Switch = N outputs. Use Switch for 3+ cases
Webhook Test/ProdTest URL shows live data in canvas. Prod URL runs silently after publish
API vs WebhookAPI = pull (you ask). Webhook = push (they notify you)
n8n vs Zapiern8n is open-source, self-hostable, supports code logic. Zapier is closed SaaS
Schedule TriggerRequires workflow to be SAVED and PUBLISHED to fire automatically
Merge ModesAppend, Combine (key match), Choose Branch, Wait for results
Error WorkflowSeparate workflow with Error Trigger — not just a node in same flow
⚡Exam Tips & Gotchas
⚠️
Trigger nodes have NO input arrow — only outgoing connections. First node = trigger.
⚠️
Data is always an array of items — not a single object. Even one record = [{ json: {...} }]
⚠️
execute_workflow MCP tool defaults to production mode (published workflow). Override with manual execution mode for testing.
⚠️
Merge node can force both IF branches to execute — even if IF sends no data down false branch, Merge causes it to run anyway.
💡
Always flowchart before building. Verify your required apps and actions exist in n8n before starting the workflow. Not everything is automatable with pure rules.
